# v2.2.14：修"两节合并"（跳转后检测恢复加速 + 静默重新武装）

## 根因（结合面板证据的时序推演）

连播点击跳转下一节 → 页面重载 → content-detect 等 6s 心跳周期才重注入 → 窗口内第 N+1 节的 playing=true 未上报 → 静默切节的 fired 锁不被播放信号重置 → **第 N+1 节播完时停播静默被锁不切**；兜底 URL 切节被"课时名未变"闸拦（detector 缺失课时名停留旧值）→ 两节合并。是否合并取决于重注入是否赶上播放开始 → "有时"。

## 修复

1. **doSplit 成功后 `silenceSplitFired = false`**：切段即重新武装静默检测（配合已有 30s 间隔防碎切）
2. **停播静默启用收紧**：`lastPlayingTs > segStartAt`（本段开始后确实观察到过播放才启用）——防切段后无 playing 时的周期性碎切
3. **tabs.onUpdated URL 变化时立即补注入 detector**（fire-and-forget，自带 3 次重试）——把重注入延迟从 6s 压到跳转即刻
4. **删除"课时名未变不切"闸**：URL 稳定 3s 已滤抖动（进度参数持续变→不稳定→不切），稳定 3s 的 URL 变化=真导航，删除后场景 B（detector 缺失）可由 URL 切节兜底
