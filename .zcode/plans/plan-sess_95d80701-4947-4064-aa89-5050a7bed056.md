# v2.2.13：修冷却的 storage.session 权限问题（连播失效根因）

## 根因（代码级实锤）

`chrome.storage.session` 默认仅 trusted 上下文（SW/popup/options）可访问，**content script 是 untrusted**——v2.2.12 把点击冷却检查（storage.session.get）放进 content script，Promise 必然 reject，`.catch(() => {})` 静默吞掉 → 点击分支永不执行 → 连播死（v2.2.11 无此调用故连播成功，版本间差异完全吻合）。

## 修复

1. **background 顶层**：`chrome.storage.session.setAccessLevel({ accessLevel: "TRUSTED_AND_UNTRUSTED_CONTEXTS" })`（try/catch）——官方 API，使 content script 可访问 session 存储（SW 每次启动执行）
2. **content-detect attemptAdvance 降级容错**：冷却检查的 get 失败/catch → **降级为直接点击**（doClick 提取）——冷却失效也不能不连播
3. manifest → 2.2.13；AGENTS 踩坑补录（storage.session 默认不对 content script 开放）；校验 + diag_e2e 回归 + 提交

## 复验

连播分节录制：弹窗点掉、顺序播下一节不跳课、每节一个文件。e2e 诊断脚本同跑确认点击层记录正常。
