# v2.2.3：连播跨帧广播（修弹窗点不掉）+ 连播结果面板化（绕反调试清日志）

## 用户反馈的关键信息（两条）

1. **站点有反调试脚本周期性 console.clear()**（用户贴的混淆代码）——[tabrec] 日志被清导致诊断盲区，改为结果上报扩展内部、面板显示
2. 切节原因样本：lesson-change（开录几秒）/ silence-gap（弹窗后）/ url-change（弹窗后）——按用户指示**本轮不碰切节**，聚焦弹窗

## 连播失效根因（架构级）

ended 事件挂在**播放器所在帧**（可能 iframe）的 content-detect 实例上，它只扫描**自己 document**；而评分弹窗「放弃评价观看下一节」在**顶层文档**——顶层实例没收到 ended、iframe 实例找不到顶层按钮，没人点击。

## 修复

1. **SW content-report**：data.ended=true 时向该 tab **所有帧广播** `{type:"try-advance"}`（sender.tab.id）——每帧各自在自己的 document 找入口，顶层/iframe 双保险
2. **content-detect**：onMessage 加 try-advance → scheduleAdvance()；attemptAdvance 每次结果（含 autoNext 未启用、未找到入口）sendMessage advance-result 上报（console.info 保留）
3. **SW advance-result**：存 session.advanceLog（最近 5 条带时间）；status 响应附加 advanceLog
4. **popup**：recTip 显示最近连播日志（如「自动连播：已点击文本「放弃评价…」」/「未找到入口」/「自动连播未启用」）
5. manifest → 2.2.3；AGENTS 更新；校验 + 提交

## 复验

Chrome 重载 → 分节录到弹窗出现 → **面板底部**应显示连播结果：已点击（成功进下一节）/ 未找到入口（把弹窗按钮 F12 元素截图发我）/ 未启用（autoNext 配置链路问题，我再查）——三种结果都直接指向下一步
