# v2.3.0：节间停止-恢复架构（弹窗期不录制，跳转成功自动续录）

## 方案（你的提议，技术可行性已论证）

播完弹窗 → 停播 5 秒确认 → **停止录制并保存当前节**（锚点保存与页面跳转解耦，offscreen 独立文档不受导航影响）→ 保持连播广播（点击弹窗）→ **跳转成功（URL 稳定）或检测到播放恢复 → 自动重新捕获开录**（新 streamId，序号延续）。

收益：节间黑屏废视频从"录了再扔"变为"根本不录"，黑屏丢弃/两节合并的整类竞态从设计上消失。

## 关键可行性确认

- **activeTab 持续性**：同站（同源）跳转保持授权，重新 getMediaStreamId 可用 ✓（该站场景）；跨域跳转会失效 → 恢复失败时通知用户手动重启录制（面板明示），第 N 节内容已安全保存
- **下一节开头可能丢 1-2 秒**（捕获建立延迟），换来节间完全无废段——净收益

## 改动

### offscreen.js（状态机）
1. 新状态 `between`（节间等待）：停播静默切段时（silence-gap/video-ended 且 autoNext）→ **不 startSegment**，改为 stopAll(keepOffscreen)——recorder.stop → finalize 保存 → 完成后进 between（**不发 recording-finished**，offscreen 文档保留）
2. **恢复触发（双源）**：between 态收到 URL 稳定变化（SW navigated 通知→onUrlChange）或 playing=true 上报 → requestCapture()（复用现有机制，新 streamId）→ beginCapture → startSegment（**seq 延续**，currentLesson 已被识别更新为新节名）
3. requestCapture 失败（activeTab 失效等）→ state=idle + recording-finished{error} → 面板提示手动重启
4. between 期：定时兜底广播继续（45s）；用户点停止 → 干净结束关文档
5. 切段相关竞态代码（黑屏丢弃/实质内容前提）随 between 废除——节间不再录，无需丢弃

### background.js
- 新消息 `segment-paused`：不清 session.recording、不关 offscreen 文档、badge 显示"‖"（节间等待）
- onUpdated URL 变化 → 通知 offscreen（navigated，恢复触发源）+ 补注入 detector（已有）
- between 期心跳/audible 上报保持

### popup
- between 态：chip「等待下一节」、主行显示当前识别标题、禁用暂停、停止可用
