# 暂停碎片：真实浏览器取证 → 按证据修复

## 已确认的代码事实（读码实锤）

1. **v2.8.1 前提挡错了地方**：`offscreen.js:797` 的 `lastPlayingTs > segStartAt` 只在「即刻切」分支（:795-806）。前提不成立时**不 return，顺序落入「URL 稳定切段」分支（:807-829）**——该分支无「本段播过」前提，且 segUrlMode=true 时课时名否决（:821）被显式跳过 → 暂停态 URL 噪声每轮照样 `doSplit("url-change")` 保存碎片（周期 ≈ URL 变化周期 + 3s + 1.5s）。
2. **45s 连播兜底广播不看播放态**（:1095-1098）：暂停静止段照发 → content-detect 暂停守卫（只拦「有视频在播」）不拦 → doClick 命中暂停控制栏 next/close 类按钮即报 advance-clicked → :1142-1145 `cur.bytes≥2MB` 即切段。周期 ≈ 45+2 = **47s，与 YouTube 碎片周期精确吻合**；且每环 between→resumeCapture 重置 resumeTs → idleWrap 60s 收工永不触发（解释「2 分钟不停」）。
3. **B 站 ~15s 无单一强吻合链路**，候选：①上述稳定切段回落（B 站心跳参数 ~10s + 4.5s）；②暂停浮层预览视频使顶层 playing 恒 true（击败 v2.8.1 前提，回到即刻切）或其 ended 事件满足 endedSeen（打开 entry-visible 通道）。

**以上仍是推演。暂停态两站的真实信号流（顶层 URL 是否真变/周期/参数名、playing 真值、ended 源）从未被观测过。**

## 阶段 1：纯页面观测（新脚本 scripts/diag_pause_page.py，不加载扩展）

回答「暂停 120 秒内页面到底发生什么」：
- Edge 打开 B 站真实多 P 视频页（YouTube 加 `--proxy-server=127.0.0.1:7897`，不可达则只测 B 站并说明）
- CDP 注入观测脚本（500ms 轮询 + 事件钩子）记录：
  - 顶层 `location.href` 变化流：原始值 + 扩展同款指纹逻辑（剥 t/t2/time/start/progress/at/ts/timestamp + hash）对比 → 每次变化是否被判「内容标识变化」、周期多少、变的是哪个参数
  - `history.pushState/replaceState` 钩子
  - 页面**全部 `<video>` 清单**与 play/pause/ended 事件 + 每轮 paused 快照——识别暂停浮层预览视频是否自动播放、其 ended
  - `[class*=next i][class*=skip i][class*=continue i]` 可见元素清单变化（模拟 advanceEntry 信号源）
- 驱动：video.play() 15s → video.pause() → 采样 120s → 导出事件时间线

## 阶段 2：扩展全链路复现（新脚本 scripts/diag_pause.py，基于 diag_e2e.py 框架）

- Edge + `--load-extension` + B 站多 P 页 → Ctrl+Shift+Y 授权 → SW 注入 `offscreen-schedule`（分节 + `segUrlMode:true` + `silenceWrapSeconds:60`，autoNext 默认开）
- video.play() 15s → pause() → 1s 步进采样 120s：offscreen-status（state/seq/segCount/lastSplit.reason/signals.playingAgo/urlLog）+ advanceLog + downloads 文件时刻
- **判别表（预先定死，按输出直接归因）**：

| 观测特征 | 结论 |
|---|---|
| advance-pause×1 后周期性 url-change，playingAgo 大（>30s） | U2 稳定切段回落 |
| 周期性 url-change，playingAgo 小（<3s） | U1 浮层预览在播（阶段 1 video 清单佐证） |
| ~47s 周期 advance-clicked | 环 A 兜底广播点击（advanceLog 显示点了什么） |
| entry-visible | 环 E' 浮层 ended |

- 若授权链路再卡死（历史环境故障）：降级为阶段 1 证据 + 面板观测面，交用户在其 Chrome 跑诊断脚本补一轮数据

## 阶段 3：按证据修复（原则：语义判定，不动连播主链路）

- **U2** → 稳定切段分支（:807）补同款「本段播过」前提——静止段一律不切，交 idleWrap 60s 收工
- **环 A** → advance-clicked 在 recording 态的切段路径加播放态前提（本场已播过且当前停播 = 暂停静止期，不得被点击切段）；between 态 resumeCapture 保留，但 resumeTs 重置导致收工失效需一并处理（暂停静止期多次恢复不应无限推迟收工）
- **U1/E'** → playing/ended 信号限定主视频（如尺寸/时长阈值），或对应前提强化
- 修复原则遵守既有约定：语义判定优于时间滤波、多信号并存不整体删除（目标是「暂停静止段冻结切节、只等恢复或收工」，不是拉长定时器）
